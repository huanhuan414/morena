# 项目经理执行任务单

## 0. 执行规则

- 严格按阶段顺序执行，不允许跳阶段并行开发。
- 每阶段必须先完成“冻结产物”，再进入开发。
- 每阶段必须通过“阶段验收”，才允许进入下一阶段。
- 项目经理是唯一排期入口，产品经理不直接跨过项目经理给开发下发需求。
- 架构师是规则冻结唯一出口，开发不允许自定义状态、字段、路由、平台口径。

## 1. 角色职责

### 产品经理
- 冻结业务主链、页面入口、验收标准。
- 冻结平台策略矩阵、凭证要求、失败处理策略。
- 对“做什么”负责，不对“怎么实现”拍技术方案。

### 项目经理
- 维护任务顺序、里程碑、阻塞项、验收记录。
- 组织冻结会、联调会、回归会。
- 控制任务流转：`待冻结 -> 已冻结 -> 开发中 -> 联调中 -> 待验收 -> 已完成`。

### 架构师
- 冻结状态机、字段字典、DTO 契约、导航矩阵、兼容层策略。
- 输出禁止事项和边界。

### 前端开发
- 只消费冻结后的 DTO 与状态机。
- 负责路由、回流、状态展示、交互闭环、跨端兼容。

### 后端开发
- 负责状态推进、聚合逻辑、接口契约、字段兼容、数据归档。

### 测试/联调
- 只按主链和异常链路验收，不按页面孤立点测。

## 2. 总执行顺序

1. 阶段 A：规则冻结
2. 阶段 B：分身链路收敛
3. 阶段 C：订单分发与处理链路收敛
4. 阶段 D：发布域模型与反馈验收收敛
5. 阶段 E：导航与回流治理
6. 阶段 F：支付与订阅运营闭环
7. 阶段 G：我的分身中长期产品能力执行化

## 3. 阶段门禁

### A -> B 门禁
- 已产出状态机冻结文档
- 已产出字段字典
- 已产出 DTO 契约
- 已产出页面导航/回流矩阵

### B -> C 门禁
- `avatarId` 参数口径冻结
- 托管字段口径冻结
- 好友上下文与创建回流链路通过回归

### C -> D 门禁
- 接单、生成、验收只有单一主链
- 订单状态只有单一事实源
- 订单详情 DTO 冻结并回归通过

### D -> E 门禁
- 发布平台 canonical 口径冻结
- 发布状态机冻结
- 发布反馈与验收闭环通过

### E -> F 门禁
- 主要页面路径与注册一致
- 跳转 API 使用规范通过回归
- 回流与刷新机制通过回归

### F -> G 门禁
- 订阅权益、支付回写、异常单处理闭环通过

## 4. 阶段 A：规则冻结

### A-1 冻结业务主链
- 负责人：产品经理
- 依赖：无
- 输出：
  - 单一业务主链说明
  - 单一验收主链说明
- 验收：
  - 主链固定为 `分身发现/创建 -> 托管配置 -> 派单 -> 接单 -> 内容生成 -> 发布 -> 反馈 -> 验收 -> 完结`
  - 不再保留多个备选主链

### A-2 冻结状态机
- 负责人：架构师
- 依赖：A-1
- 输出：
  - 订单状态机
  - dispatch 状态机
  - processing 状态机
  - publish 状态机
- 验收：
  - processing 状态固定为 `queuing / generating / preview / publishing / published / awaiting_acceptance / completed / failed`
  - 每个状态有唯一含义、唯一前驱、唯一后继约束

### A-3 冻结字段字典
- 负责人：架构师
- 依赖：A-2
- 输出：
  - `avatar`
  - `order`
  - `dispatch`
  - `processing`
  - `publishEvidence`
  - `publishMetrics`
- 验收：
  - 同一业务概念只有一个主字段
  - 兼容字段有迁移策略

### A-4 冻结 DTO 契约
- 负责人：架构师
- 依赖：A-3
- 输出：
  - 订单详情 DTO
  - 处理状态 DTO
  - 发布反馈 DTO
  - 验收 DTO
- 验收：
  - 前后端接口样例齐全
  - 不允许页面层自行兜底猜字段

### A-5 冻结导航与回流矩阵
- 负责人：产品经理 + 架构师
- 依赖：A-1
- 输出：
  - 页面入口矩阵
  - 页面回流矩阵
  - 必填路由参数矩阵
- 验收：
  - 以 `src/app.config.ts` 为唯一注册事实源
  - 每个页面有来源页、目标页、回流页、必填参数

### A-6 冻结风险清单
- 负责人：项目经理
- 依赖：A-2, A-3, A-4, A-5
- 输出：
  - 参数双轨清单
  - 字段双轨清单
  - 状态双轨清单
  - 导航断裂清单
- 验收：
  - 每个风险有责任人、优先级、处理阶段

## 5. 阶段 B：分身链路收敛

### B-1 统一分身参数协议
- 负责人：前端开发 + 后端开发
- 依赖：A-3, A-4, A-5
- 输出：
  - 统一 `avatarId` 口径
  - 清理 `id/avatarId` 双轨入口
- 验收：
  - 分身主页、推荐页、好友页、订单链路只用 `avatarId`

### B-2 统一托管字段协议
- 负责人：后端开发
- 依赖：A-3
- 输出：
  - `trust_enabled / is_hosted / isHosted / hosting_enabled` 主次关系与迁移策略
- 验收：
  - 写入、读取、推荐、派单判断使用同一口径

### B-3 修复好友上下文
- 负责人：前端开发
- 依赖：A-5, B-1
- 输出：
  - 用户级好友入口
  - 分身级好友上下文入口
- 验收：
  - 缺少 `avatarId` 时有明确引导
  - 从分身管理进入好友页不丢上下文

### B-4 修复创建后回流刷新
- 负责人：前端开发
- 依赖：A-5
- 输出：
  - 创建成功后的返回与刷新方案
- 验收：
  - `mind-chat`、`avatar-manage`、创建入口页刷新一致

### B-5 收敛分身链路回归
- 负责人：测试/联调
- 依赖：B-1, B-2, B-3, B-4
- 验收：
  - 创建 -> 查看 -> 管理 -> 好友 -> 返回 全链路通过

## 6. 阶段 C：订单分发与处理链路收敛

### C-1 统一接单入口
- 负责人：前端开发 + 后端开发
- 依赖：A-2, A-4, A-5
- 输出：
  - 接单接口返回 `requestId / orderId / avatarId / dispatchId`
  - 接单后统一跳转主链入口
- 验收：
  - 不再存在“有的跳 content-creation，有的跳 order-processing”的分叉

### C-2 统一订单主链
- 负责人：前端开发
- 依赖：C-1
- 输出：
  - `pending-order`
  - `generated-content`
  - `order-detail`
  - `order-processing`
  - `order-content-creation`
  的单一路由链
- 验收：
  - 旧旁路页面仅允许做桥接，不再承载第二套流程

### C-3 统一订单状态事实源
- 负责人：后端开发
- 依赖：A-2, A-3
- 输出：
  - `OrderService` 作为唯一状态聚合器
  - `OrderProcessingService`、`ContentGenerationService` 只回调统一聚合器
- 验收：
  - 仓库内不再存在多套订单状态计算规则

### C-4 统一订单详情 DTO
- 负责人：后端开发
- 依赖：A-4, C-3
- 输出：
  - 统一订单详情聚合结构
  - 统一 `avatarStats.status`
- 验收：
  - 订单详情页不再自行做旧状态兼容推断

### C-5 统一验收入口
- 负责人：前端开发 + 后端开发
- 依赖：C-2, C-3
- 输出：
  - 验收页为唯一验收入口
  - 订单详情不允许直接改 `completed`
- 验收：
  - 验收通过只走 `order-processing/accept/:id`
  - 驳回只走统一 revision 流程

### C-6 订单主链回归
- 负责人：测试/联调
- 依赖：C-1, C-2, C-3, C-4, C-5
- 验收：
  - 发单 -> 派单 -> 接单 -> 生成 -> 验收 -> 完成 全链路通过

## 7. 阶段 D：发布域模型与反馈验收收敛

### D-1 冻结 canonical 平台映射
- 负责人：架构师

  - 平台策略矩阵
- 验收：

  - 存储与返回统一 canonical key

### D-2 冻结发布反馈字段字典
- 负责人：架构师
- 依赖：A-3, D-1
- 输出：
  - `link`
  - `screenshots`
  - `submitTime`
  - `operator`
  - `metrics`
- 验收：
  - 每个平台的最小凭证要求可验证

### D-3 落地发布引导与绑定阻断
- 负责人：前端开发 + 后端开发
- 依赖：D-1, D-2
- 输出：
  - 未绑定账号阻断规则
  - 发布引导页统一逻辑
- 验收：
  - 平台要求绑定时，阻止进入发布并明确引导绑定

### D-4 落地反馈与重试机制
- 负责人：前端开发 + 后端开发
- 依赖：D-2

  - 反馈补提通过

### 任务状态

## 12. 项目经理阶段验收模板

### 冻结验收
- 是否有书面文档
- 是否有责任人签收
- 是否禁止多口径继续开发

### 开发验收
- 是否附接口样例
- 是否附页面入参
- 是否附状态迁移说明
- 是否附自测结果

### 联调验收
- 是否覆盖主链
- 是否覆盖异常链
- 是否覆盖回流链

### 交付验收
- 是否回写任务状态
- 是否同步风险关闭
- 是否更新冻结文档
