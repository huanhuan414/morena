# Task 3 Appendix：商业模式与定价策略（订阅/抽成/增值 + 单位经济）

## 3.1 订阅/抽成/增值组合策略与用户侧心智

### 目标与约束
- 目标：让用户清楚“为什么付费”，平台清楚“赚多少钱/怎么赚”，运营清楚“怎么做 A/B 与风控”，财务清楚“现金流是否安全”。
- 约束：避免“双重收费”造成转化下降；同时覆盖 AI 推理成本、验真成本、支付成本与坏账风险；兼容 B2C（个人/工作室）与 B2B（代理商/品牌方）两类客群。

### 收费要素拆分（避免混淆）
- **订阅（Subscription）**：为“持续可用的能力/权限”付费，强调“工具与确定性”，如：托管能力、并发上限、分身/账号管理、生成额度、优先队列、快速结算。
- **抽成（Take Rate / Commission）**：为“撮合与履约保障”付费，强调“成交与风险承担”，以订单结算金额为基准；可与争议仲裁/验真服务绑定。
- **增值（Add-ons）**：为“可选的加速/增强/保障”付费，强调“按需购买、可解释”，如：加急分发、额外生成包、人工验真、加速回款、团队席位、品牌模板包。

### 组合策略（推荐的两条主线）
#### 策略 A（偏供给侧）：订阅为主 + 低抽成
- 适用：A 类内容接单个人/工作室（供给侧）为主的阶段。
- 用户心智：我付订阅费获得“接单工具与更高成功率/更稳定回款”，平台抽成只覆盖撮合与争议成本。
- 结构建议：
  - 免费层：允许体验（低额度/低并发/更高抽成/更慢回款）。
  - 订阅层：提供核心生产力与确定性（更高托管与并发、优先分发、较低抽成、较快回款）。

#### 策略 B（偏需求侧）：抽成为主 + 可选保障增值
- 适用：B 类品牌商/跨境卖家等需求方可规模化付费阶段。
- 用户心智：我按成交支付服务费，平台提供“可验真交付”与争议处理，增值项用于保障与效率。
- 结构建议：
  - 订单服务费（抽成）：与验真/争议治理绑定，形成“服务闭环”。
  - 可选保障：加急、人工验真、交付 SLA、优先客服、模板包等。

### 避免“双收费”的规则（统一口径）
- 同一价值不要在两个计费项重复收取：例如“验真保障”要么包含在抽成里，要么作为增值项，不要同时写进订阅权益与抽成理由。
- 让用户可计算：在订单创建/接单前明确展示“预计到手/预计平台收费/预计回款时间”。
- 以“交换条件”减少阻力：订阅带来明确的可量化收益（更低抽成、更多托管并发、更快回款），用户才能接受“先付再赚”。

### 关键可调参数（用于 A/B 与风控）
- 抽成：平台服务费率、阶梯费率（按 GMV/等级/复购）、封顶/保底。
- 订阅：月/季/年、自动续费、试用期、赠送额度/优惠券。
- 回款：T+0/T+3/T+7、快速回款费率、保证金/风险准备金比例。
- 增值：加急费、人工验真费、额外生成额度包、团队席位与协作能力。

## 3.2 定价分层与权益（含风控约束与成本项）

### 定价对象与分层轴
- 供给侧（接单者/工作室）：围绕“托管能力 + 产能上限 + 回款确定性”定价。
- 需求侧（发单者/品牌方）：围绕“交付 SLA + 可验真 + 规模化管理”定价。
- 分层轴（建议同时满足 2–3 条即可形成清晰差异）：
  - 产能：可托管分身数、并发接单数、平台账号数
  - 成本：AI 生成额度（按 token/次数/任务包）、媒体生成额度（图/视频）
  - 确定性：优先队列、加急通道、争议仲裁、人工验真
  - 现金流：回款速度、提现次数/额度、风控审核强度（更快通常伴随更多风控要求）

### 供给侧订阅分层（示例结构，金额留给后续定价实验）
- **Free（体验）**
  - 低托管上限、低并发、基础生成额度
  - 默认较高抽成或固定服务费
  - 回款周期较长（默认风控）
- **Pro（个人高频）**
  - 更高托管上限与并发、更多生成额度
  - 抽成下调（或阶梯下调）
  - 支持快速回款（可选增值）
- **Studio（工作室）**
  - 多分身/多账号管理、协作与权限
  - 更低抽成区间、更高回款上限
  - 支持团队席位（增值或包含）

### 需求侧（发单）分层（示例结构）
- **Pay-as-you-go（按单）**
  - 订单服务费（抽成）+ 可选保障增值（人工验真/加急）
  - 适合低频或试用
- **Business（规模化）**
  - 低抽成或服务费封顶 + SLA 与优先支持
  - 多项目/多账号、统一对账、发票与财务能力
- **Enterprise（大客户）**
  - 定制 SLA、风控白名单、专属客服
  - API/批量导入、专属模板、合规模块

### 权益设计的“必含项 vs 增值项”
- 必含项优先覆盖“主链成功率”：托管能力、并发/上限、基础生成额度、基础验真与回传能力、基础提现。
- 增值项聚焦“加速/保障/规模化”：加急队列、人工验真、快速回款、争议保障、团队席位、模板包、API。

### 风控与合规约束（写进权益，而不是写进运营口头规则）
- 身份与资质：实名/KYC、平台账号绑定校验、黑灰产拦截。
- 订单准入：预算下限、类目/平台规则校验、敏感内容与违规词检测。
- 履约风控：异常生成频率、异常接单拒单、重复素材、批量刷单特征。
- 验真风控：链接真实性校验、截图/凭证一致性、重复提交与篡改检测。
- 资金风控：新用户/高风险用户回款延迟、提现限额、风险准备金、争议期冻结。
- 分层差异化：更快回款/更高额度必须绑定更强风控（例如更高等级 KYC、保证金、更多证据要求）。

### 成本项清单（用于定价与毛利核算）
- AI 推理成本：LLM token、图像/视频生成、重试与回滚成本。
- 人工成本：客服、人工验真、争议仲裁、运营审核。
- 基础设施：存储/带宽、队列与任务编排、日志与审计。
- 支付与财务：支付通道费、提现手续费、汇兑（如跨境）、发票与税务处理。
- 风控损失：退款/拒付、坏账、作弊补贴损失、风险准备金占用。
- 增长成本：优惠券与补贴、邀请返利、投放与渠道费用。

## 3.3 单位经济模型框架（收入、毛利、现金流）

### 核心单位与口径
- 单位：以“**已验真并完成结算的订单**”作为单位（与北极星 Verified GMV 对齐）。
- 时间：按周/月滚动计算，同时保留 cohort（按注册月/首单月）视角。

### 收入结构（每单）
- 订单金额（GMV）：`gmv`
- 平台抽成收入：`commission_revenue = gmv * take_rate`
- 订阅摊销到单：`subscription_revenue_per_order = subscription_arpu / orders_per_paying_user`
- 增值收入：`addon_revenue`（加急、人工验真、额度包、快速回款等）
- 退款/赔付：`refund_cost`（负收入/费用）
- 每单净收入：`net_revenue = commission_revenue + subscription_revenue_per_order + addon_revenue - refund_cost`

### 变动成本（每单）
- 推理成本：`ai_cost`（token 与媒体生成，含重试）
- 验真成本：`verification_cost`（自动校验 + 人工抽检/仲裁）
- 支付成本：`payment_fee`（收款/提现）
- 客服与运营成本：`support_cost`
- 风控损失与准备金摊销：`risk_cost`
- 每单总变动成本：`variable_cost = ai_cost + verification_cost + payment_fee + support_cost + risk_cost`

### 贡献毛利与毛利率
- 每单贡献毛利：`contribution_margin = net_revenue - variable_cost`
- 贡献毛利率：`cm_rate = contribution_margin / gmv`（也可用 `/ net_revenue` 口径作为补充）

### 固定成本与经营杠杆（按月）
- 固定成本：研发、服务器固定部分、管理费用等：`fixed_cost_monthly`
- 盈亏平衡订单量：`breakeven_orders = fixed_cost_monthly / contribution_margin_avg`

### CAC、LTV 与回本周期（cohort 视角）
- 获客成本：`cac`（按渠道/活动/邀请分别核算）
- 付费渗透与留存：订阅转化率、续费率、复购率（订单/发单）
- LTV（简化）：`ltv = arpu_monthly * gross_margin_rate * lifetime_months`
- 回本周期（简化）：`payback_months = cac / (arpu_monthly * gross_margin_rate)`

### 现金流与风控（资金安全优先级高于利润）
- 回款与结算：结算周期 `settlement_cycle_days` 影响资金占用与风险暴露。
- 争议窗口：争议期冻结 `dispute_hold_days` 与风险准备金 `reserve_rate`。
- 现金流安全检查：
  - 快速回款增值必须覆盖额外风险成本：`fast_payout_fee >= incremental_risk_cost + capital_cost`
  - 新客/高风险用户默认更长结算周期与更高冻结比例。

### 最小可用数据清单（落地所需）
- 每单：`gmv、take_rate、addon_revenue、refund_amount、ai_tokens、media_gen_count、verification_type、payment_channel_fee、payout_time`
- 每用户：`subscription_plan、subscription_revenue、orders_count、retention、channel_source、inviter_id`
- 风控：`risk_score、dispute_count、reject_reason、chargeback_flag、blacklist_flag`

### 输出模板（建议在后台/报表呈现）
- 单位经济仪表板：按平台/类目/渠道/等级拆分的 `net_revenue、variable_cost、contribution_margin、cm_rate`
- 价格实验看板：不同订阅/抽成方案的 `转化率、留存、订单成功率、毛利、退款率、提现失败率`
