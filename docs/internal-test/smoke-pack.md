# 内测 Smoke Pack（WEAPP）

目标：每次修复后，用 20–30 分钟快速确认主线闭环未回归。  
放行口径：P0=0、P1=0。

## 环境准备
- 端侧：微信小程序（真机优先）
- 账号：发单者账号 1 个、接单者账号 1 个（接单者需至少 1 个可用分身）
- 约定：所有接口走 `/api/*` 相对路径；如遇网络/域名问题先确认小程序合法域名与登录态

## Smoke-01：发单 → 支付成功 → 派单 → 接单 → 生成 → 发布反馈 → 验收通过 → 完成结算
- 发单者：新建订单，填写标题/平台/内容类型/数量，确认总价
- 发单者：支付成功后进入匹配页，点击一键派单
- 接单者：进入待接订单/广场接单，选择分身接单
- 接单者：进入处理页观察生成状态从排队/生成到预览完成（失败可重试）
- 接单者：进入发布引导，完成复制文案/保存配图，点击“完成发布”
- 接单者：进入发布反馈，提交截图/链接；如需要验证，验证通过后提交
- 发单者：进入验收页，逐个验收通过，订单进入完成态
- 接单者：收益中心可看到对应收益入账（若为待结算，应有清晰状态与解释）

预期（关键断言）
- 任一环节失败都有可操作兜底：重试/继续支付/返回详情/人工核验
- 订单状态在列表/详情/匹配/处理/验收页一致，且下一步动作明确

## Smoke-02：支付取消 → 继续支付恢复
- 发单者：创建订单后在支付页取消
- 发单者：从订单详情继续支付并成功

预期
- 不需要重新创建订单；订单状态明确为待支付；继续支付后状态自动刷新为已支付并可继续派单

## Smoke-03：生成失败 → 清理/重试 → 成功
- 接单者：在内容生成中模拟失败场景（超时/接口失败/手动触发重试）
- 接单者：执行重试后成功生成

预期
- 失败后可以恢复；不会卡死在“生成中”；不会产生多份混乱的处理记录

## Smoke-04：发布验证失败 → 兜底可提交
- 接单者：在发布反馈页触发验证失败（外部服务不可用/链接不匹配）
- 接单者：走产品兜底路径（人工核验/允许提交但标记待核验）
- 发单者：仍可在验收页看到材料并处理（可提示风险）

预期
- 不会因为验证失败导致无法提交、无法验收、订单卡死

## Smoke-05：验收驳回 → 返工 → 再提交 → 再通过（可循环）
- 发单者：对某分身的发布结果驳回并给修改意见
- 接单者：收到驳回后再次提交发布反馈
- 发单者：再次验收通过

预期
- 状态从驳回回到可执行态；返工次数不受限；不会丢失上下文（orderId/avatarId/requestId）
