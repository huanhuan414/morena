# Morena 单位经济测算与盈亏分析

## 1. 文档目的

本文档用于回答 4 个问题：

1. Morena 当前已落地的商业模型到底是什么。
2. 当前订单、订阅、补贴在单位经济上分别赚多少钱或亏多少钱。
3. 按当前代码和当前第三方服务使用方式，业务的 ROI 和盈亏平衡点在哪里。
4. 上述测算哪些部分是代码实锤，哪些部分是价格估算，是否经得起推敲。

本文档只基于当前仓库内已经落地的实现进行测算，不讨论理想模型，不讨论未来可能上线但尚未落地的抽成、套餐限制或计费改造。

---

## 2. 结论摘要

结论先行：

- 当前订单业务本身为负毛利。
- 当前模型下，订单量增长不会带来盈亏平衡，反而会放大亏损。
- 多平台分发是当前模型的核心亏损放大器，因为价格未按平台数增加，但生成成本按平台数线性增加。
- 视频单是当前最重的亏损项。
- 订阅收入有现金流价值，但在当前代码中未形成强约束的商业护城河，且不足以天然覆盖高视频占比场景下的订单亏损。
- 拉新补贴在高成本订单占比上升后，ROI 会明显恶化。

一句话概括当前模型：

`订阅带来部分现金流，但订单业务在现模型下持续负毛利；若视频与多平台占比继续提升，后期运营亏损会明显加速。`

## 3. 测算范围与方法

### 3.1 本文测算包含

- 前端订单定价
- 后端订单入库与结算
- 文本 / 图文 / 视频内容生成链路
- 第三方服务带来的可变成本
- 订阅收入
- 邀请补贴
- 月度经营场景下的可变损益
- 盈亏平衡点

### 3.2 本文测算不包含

- 人工客服逐单处理成本的精确实账
- 退款、拒付、坏账的真实历史损耗
- 云主机、数据库、日志、安全、监控的精确账单拆分
- TikHub、地图、短信等低频或次要服务的精确单次成本
- 税务、渠道分成、线下运营等更上层财务口径

因此，这是一份偏经营管理口径的测算，而不是审计级财务报表。

`订单利润 = 用户支付 - 分身分账 - 支付手续费 - AI成本 - 存储分发成本`

`用户支付 ≈ 分身分账`

所以可进一步近似为：

`订单利润 ≈ - 支付手续费 - AI成本 - 存储分发成本`

## 7. 月度运营情景测算

口径：按 `1000 个已完成分身交付单元 / 月` 测算，仅统计业务可变损益。

### 7.1 情景定义

| 场景 | 内容结构 | 平均平台数 |
| --- | --- | ---: |
| 场景 A | 70% 文本 + 25% 图文 + 5% 视频 | 1 |
| 场景 B | 60% 文本 + 30% 图文 + 10% 视频 | 1 |
| 场景 C | 40% 文本 + 30% 图文 + 30% 视频 | 1 |

### 7.2 月度结果

| 场景 | 月收入 | 分身分账 | 第三方可变成本 | 月度经营毛利 | 月度 ROI |
| --- | ---: | ---: | ---: | ---: | ---: |
| 场景 A | 4,450 | 4,450 | 970 | -970 | -9.9% |
| 场景 B | 4,900 | 4,900 | 1,770 | -1,770 | -15.3% |
| 场景 C | 9,500 | 9,500 | 4,820 | -4,820 | -20.2% |

### 7.3 平台数上升后的亏损放大

| 场景 | 平均 1 平台 | 平均 2 平台 | 平均 3 平台 |
| --- | ---: | ---: | ---: |
| 场景 A | -970 | -1,890 | -2,810 |
| 场景 B | -1,770 | -3,480 | -5,190 |
| 场景 C | -4,820 | -9,550 | -14,280 |

### 7.4 月度情景结论

- 当前订单业务在 3 个模拟场景中全部为负毛利。
- 视频占比越高，亏损越深。
- 多平台占比越高，亏损越快。
- 当前模型下，订单增长不会自动带来经营改善。

| 事项 | 依据 | 可信度 |

### 11.3 因此本文是否经得起推敲

答案分两层：

1. 作为经营判断，经得起推敲。
2. 作为审计级财务报表，还需要真实账单校准。

最稳的不是“图文单亏 0.72 还是 0.80”，而是下面这 3 个结构结论：

- 当前订单收入几乎全部分出，平台没有真实留存。
- 当前价格没有按平台数上升，但成本按平台数线性增加。
- 当前视频单是高风险亏损项。

只要这 3 个结构不变，本文关于“订单负毛利、多平台放大亏损、视频导致模型恶化”的方向性结论就不会变化。

## 12. 还需要补哪些数据，才能把模型升级为财务级模型

建议尽快补以下真实经营字段：

| 类别 | 建议字段 |
| --- | --- |
| 订单收入 | `order_gmv`、`platform_net_revenue`、`creator_payout_total` |
| AI 成本 | `llm_cost`、`image_cost`、`video_cost`、`cost_per_platform` |
| 媒资成本 | `storage_cost`、`cdn_traffic_cost` |
| 运营损耗 | `refund_cost`、`after_sales_cost`、`subsidy_cost` |

补齐后可进一步直接计算：

- 单订单真实毛利
- 单用户 LTV
- 视频单真实 ROI
- 多平台分发真实边际成本
- 订阅对订单的真实补贴效率

## 13. 最终判断

按当前代码、当前定价、当前结算和当前第三方服务使用方式测算：

- 订单业务本身为负毛利。
- 图文单为中度亏损，视频单为重度亏损。
- 多平台分发是当前最明显的亏损放大器。
- 订阅收入只能部分对冲订单亏损，无法天然修复订单模型。
- 订单量越大，不会越接近打平，反而越依赖订阅收入补贴。

最终管理判断可以写成一句话：

`当前模型不是“先亏后赚”，而是“订单每成交一次先亏一次”；若不尽快补上平台抽成、平台数计价、视频成本约束与真实成本回填，后期运营亏损会随业务规模同步放大。`
